# CI/CD Pipeline Engineering

## Introduction

CI/CD platforms are the foundation of modern software delivery.

A Senior Platform Engineer designs systems that allow hundreds of engineers to:

- Build software consistently
- Test changes automatically
- Deploy safely
- Release faster
- Recover quickly from failures

The goal is not just automation.

The goal is:

```
Fast Delivery

+

High Reliability

+

Developer Self-Service
```

---

# Continuous Integration (CI)

## Definition

Continuous Integration automatically validates code changes when developers commit code.

Typical CI activities:

- Compile code
- Run tests
- Scan security issues
- Build artifacts

---

# Continuous Delivery (CD)

## Definition

Continuous Delivery automates preparing software for release.

Example:

```
Code

 |

Build

 |

Test

 |

Package

 |

Ready for Production
```

---

# Continuous Deployment

## Definition

Continuous Deployment automatically releases approved changes into production.

Example:

```
Git Commit

 |

Pipeline

 |

Production Deployment
```

- Docker image
- Binary
- Package

## Test Stage

Purpose:

Validate correctness.

Examples:

- Unit tests
- Integration tests
- Security tests

## Release Stage

- Kubernetes deployment

# GitHub Actions

## Definition

GitHub Actions is a workflow automation platform integrated with GitHub.

It can automate:

- CI pipelines
- Deployment workflows
- Repository automation

---

# GitHub Actions Components

## Workflow

Definition:

A YAML file defining automation steps.

Location:

```
.github/workflows/
```

---

## Job

Definition:

A group of steps executed on a runner.

Example:

```
Build Job

Test Job

Deploy Job
```

---

## Step

Definition:

An individual command or action.

Example:

```
Install dependencies

Run tests

Build image
```

---

## Runner

Definition:

A machine that executes workflow jobs.

Types:

- GitHub-hosted runners
- Self-hosted runners

# Pipeline Security

CI/CD systems are production access points.

Security concerns:

- Secret exposure
- Unauthorized deployments
- Dependency attacks
- Malicious code execution

---

# Secrets Management

Bad:

```
Password stored in YAML
```

Good:

```
Pipeline

 |

Secret Manager

 |

Temporary Credential
```

---

# Least Privilege Pipelines

A pipeline should only access required resources.

Example:

Build pipeline:

Can:

```
Read Repository

Build Image
```

Cannot:

```
Delete Production Resources
```

# Artifact Versioning

Good practice:

Avoid:

```
latest
```

Prefer:

```
application:v1.4.2
```

Benefits:

- Rollback
- Traceability
- Reproducibility

---

# Build Reproducibility

## Definition

A build should produce the same output from the same source.

Achieved through:

- Locked dependencies
- Versioned tools
- Immutable artifacts

# Deployment Strategies

## Rolling Deployment

Replace instances gradually.

Advantages:

- Simple
- Kubernetes default

Risk:

Bad version affects users gradually.

---

## Blue/Green Deployment

Two environments:

```
Blue

Current Version


Green

New Version
```

Traffic switches after validation.

---

## Canary Deployment

Release to small percentage first.

Example:

```
95% Old Version

5% New Version
```

Monitor:

- Errors
- Latency
- Business metrics

# Incident: CI Pipeline Suddenly Slow

## Symptoms

Build time increased:

```
10 minutes -> 60 minutes
```

---

## Investigation

Check:

1. Runner availability
2. Dependency downloads
3. Cache effectiveness
4. External services

---

Possible causes:

- Runner shortage
- Dependency repository slowdown
- Large artifacts
- Resource exhaustion

# Senior Interview Questions

## Easy

### What is the difference between CI and CD?

Answer:

CI validates and integrates code changes. CD automates preparing and delivering software safely.

---

## Medium

### How would you design CI/CD for hundreds of engineers?

Answer:

"I would create standardized pipelines, reusable templates, secure runners, artifact management, deployment automation, and self-service workflows."

---

## Hard

### How do you make CI/CD reliable?

Answer:

"I focus on reproducibility, isolated runners, caching, artifact versioning, observability, security controls, and automated rollback."

---

## Staff Level

### How would you build a developer delivery platform?

Answer:

"I would treat CI/CD as a platform product. Provide paved roads, reusable workflows, secure execution environments, deployment integrations, metrics, and self-service onboarding."

# Common Mistakes

## Mistake 1

Giving pipelines excessive permissions.

Problem:

Security risk.

---

## Mistake 2

Using mutable artifacts.

Example:

```
latest
```

Problem:

Cannot reproduce releases.

---

## Mistake 3

Making every team create pipelines independently.

Problem:

Duplicated effort and inconsistent practices.

---

# Key Takeaways

A mature CI/CD platform provides:

- Automated builds
- Reliable testing
- Secure pipelines
- Artifact management
- Progressive delivery
- Developer self-service

The platform engineer's goal:

Enable teams to ship quickly without sacrificing reliability or security.
